Abstract

HTML Capsule is anti-context-loss infrastructure: an open specification for sealed, self-contained HTML artifacts so that useful AI work survives across tools, time, sessions, and platform churn — not as an attack on AI platforms, but as durable infrastructure complementary to them. One file, twelve rules, five required inline blocks, zero network dependencies. The format treats HTML as a memory object — human-readable, machine-readable, and provenance-bearing in a single envelope. The central claim is multi-producer interop: large language models, deterministic compilers, and human authors all produce the same envelope shape. The claim is supported by 30+ LLM-produced capsules across Claude, ChatGPT, and Gemini; at least one third-party compiler whose output round-trips through the reference validator at 26/26 from spec prose alone; and the spec's own evolution from v0.1.0 through v0.3.5 in reactive response to empirical findings rather than anticipatory design.

Position in the lifecycle

Findings · O1 — O5

O1 · substrate

HTML is becoming the default output format for AI-assisted work.

The substrate shift surfaces in prompting practice, not in document-format discussion. Independent voices treat HTML as the natural target for LLM output rather than a power-user trick.

“Markdown has become the dominant file format used by agents to communicate with us… But as agents have become more and more powerful, I have felt that markdown has become a restricting format… I’ve started preferring HTML as an output format instead of Markdown.”— Thariq Shihipar
“structure your response as HTML”— Andrej Karpathy, on prompting
O2 · principle

File over app remains the durable preservation primitive.

Artifacts that survive depend on file-level portability. Plugin-mediated app environments reintroduce the fragility they were meant to escape; the file is the unit that endures across software generations.

“If you want to create digital artifacts that last, they must be files you can control, in formats that are easy to retrieve and read.”— Steph Ango (Kepano), File over App
O3 · lineage

Lineage is a more tractable problem than HTML diffs.

Raw HTML diffs are noisy because HTML is closer to a runtime than a writing format. Identity, version, and parents are addressable through the manifest. Once an artifact has a UUID, a capsule_version, and a parents[] chain, review tooling can be layered on the spec rather than forcing humans to read raw HTML; semantic diffs over the five named blocks become tractable.

O4 · live edit

A live-editing and collaboration layer is emerging upstream of the seal step.

Claude Design (Anthropic Labs), html-docs.com (Raunaq Bhutoria), and Workplane (Matan / matanrak) have converged on a publish-comment-revise loop with MCP as the common integration substrate. The Capsule format sits downstream as the seal step and remains editor-agnostic — any of these tools can produce a conforming envelope.

O5 · share links

Share links inside LLM platforms do not compose across platforms.

Every major chat platform offers share links, but they function as platform-internal viewers rather than portable artifacts. A ChatGPT share link handed to Claude does not transfer structured conversation state. A sealed file does.

Scope (what this is not)

  • Not a new file format. It is HTML.
  • Not a new editing surface. Canvas and Artifacts already cover that.
  • Not a knowledge graph or universal ontology. Per-type data schemas welcome.
  • Not anti-platform. Anti-context-loss.
  • Not a standard you have to comply with. A loose discipline.
  • Not finished. Active research.

Methods

The work proceeds as iterative spec evolution against real artifacts. Three production paths are exercised in parallel: deterministic compiler output (Python stdlib reference implementation), prompted LLM output (Claude, ChatGPT, Gemini via the Core spec as conversational context), and hand-authored or hybrid output (compiler-shaped Python generators authored by an LLM, then frozen). Each iteration produces fixtures; fixtures are validated; failures and honest deviations are recorded as findings in the research log.

The spec moves reactively rather than generatively. Usage drives; thesis judges. Every observed deviation, failure, convention, or under-use is sorted into one of four moves on the spec:

MoveTriggered byExample
Loosenhonest deviation — LLM reaches for a more accurate value than the spec anticipatedsource.origin: "web_research"
Tightenrecurring mechanical failure — same bug class across batchesrule 12 (pre-render content)
Documentemergent convention — LLMs invent a useful pattern unpromptedembedded_media field, sources[] array
Guideunderexplored option — useful behavior LLMs aren't choosing on their ownv0.1.4 thoroughness + sources guidance

Loosening, tightening, documenting, and guiding are not opposites — they are four flavors of one reactive mechanism applied to different observations. The thesis stays constant; the spec is always catching up. Manual capsule construction has been tested across content scales from text-only landing pages to a 13.7 MB GeoJSON-backed exploration map. External review by independent agents and third-party producers occurs at each iteration. The spec advanced from v0.1.0 to v0.3.5 between 2026-05-15 and 2026-05-21.
