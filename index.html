§ I. Four questions

Archive. Share. Fork. Export.

The things raw HTML artifacts don't answer on their own. Capsule is the discipline that makes them answer — by construction, not by hosting.

i. Archive

How do you archive it?

It's just a .html file. Save it anywhere — Dropbox, USB, GitHub, an inbox, a folder on disk. The manifest makes the file self-describing for a future reader.

no externals · core rule 02

ii. Share

How do you share it?

The bytes are the artifact. No host required, no link to expire, no platform to revoke access. Once it reaches a recipient, it's theirs.

cannot be unshared · core rule 10

iii. Fork

How do you fork it?

The manifest's parents[] field records lineage. Paste a capsule into a new LLM session; the next one it produces knows what it built on.

parents[] · manifest field

iv. Export

How do you get it out of your LLM?

Paste the produce prompt from the spec. Out comes a sealed .html you can save — not a link inside the chat, not a hosted artifact you depend on, just bytes you control.

produce prompt · CAPSULE_CORE.md

Tools, not apps.

Capsules can have rich runtime tools — measure, filter, annotate, search, export — without becoming applications. The line is the JavaScript-off test: does the substance of the content depend on JS to exist? If no, it's an interactive archive — tools query the content but don't generate it. If yes, it's an app, and the spec says no.

Mintel's exploration-map capsules ship click-to-measure and click-to-find-coordinates. With JS off, the map still renders (via the static image fallback), the legend and attribution are still there. The tools are gone; the substance isn't.

Read the spec — §2.3 Rendering Model

File over app, taken further.

Steph Ango's principle says your work should live in files you control, in formats that outlive any specific app. Capsule agrees — and pushes it one step further: not just the data, but the presentation. The HTML file carries its own styles and rendering. No app dependency, no plugin layer, no theme to install. The file is the experience.

Adjacent voices

People thinking about this from related angles, organized by the lifecycle layer each occupies. Not endorsements either way — just the conversation Capsule is part of.

Format & substrate observers

Thariq Shihipar

"HTML is the new markdown."

Public observation that LLMs and agents are emitting single self-contained HTML files as their default artifact format. The substrate observation Capsule builds on.

Read on X

Andrej Karpathy

LLM wiki + "structure your response as HTML."

Two adjacent angles. His LLM-wiki gist proposes a personal knowledge base of plain markdown files that an LLM authors and maintains. His prompting tip lays out a four-step progression (raw text → markdown → HTML → eventually interactive neural simulations) and names HTML as the current best default. Capsule sits between — HTML as the substrate, with a contract on the file.

Read the archive

Blake Crosley

"HTML is the format AI agents want."

Argues HTML preserves spatial structure, interaction, and density in a way markdown linearizes away. The control-surface framing: HTML as what agents should produce, live and inspectable.

Tracking the HTML-from-LLM wave.

Has written extensively about LLM-emitted HTML on his blog and amplified Thariq's substrate observation. Also runs Datasette — a different shape of single-file substrate (SQLite with a built-in HTML viewer).

Layers Capsule composes with

Raunaq Bhutoria — html-docs.com live editing

"Create beautiful docs and webpages with your Agents."

Engineer at Meta. Built html-docs.com as a live collaboration layer for agent-generated HTML — agents publish via Claude Code skill / MCP / HTTP API, humans review with comments, agents read the comments and revise. The agent ↔ human review loop named as a workflow primitive. Endorsed by Karpathy + Thariq on the homepage. Complementary lifecycle layer to Capsule's seal step — html-docs is where the work is iterated; Capsule is what it becomes when sealed.

Read on html-docs.com

Matan (matanrak) — Workplane live editing

"Turn AI outputs into live pages." / "The working plane between AI and humans."

Independent live-editing layer, second implementation of the same pattern as html-docs.com. MCP-first, multi-agent (Claude Code, Codex, Cursor, Devin, Claude Desktop). Free for individuals, no account required for commenters. Open-source agent skill at work-plane/workplane-skills (MIT). Maintainer is Matan (GitHub: matanrak), based in Israel. The convergence with html-docs.com on the same workflow shape (publish → comment → agent revises) is the empirical signal — documented as F22.

Read on workplane.co

Utkarsh Sengar — htmlbin.dev hosting

"Agent-first HTML hosting."

Launched htmlbin.dev in May 2026 (about the same week as htmlcapsule) — public hosting infrastructure for agent-emitted HTML, short URLs, /raw endpoint. Independent convergence with the MinDev hosting pattern — complementary layer to Capsule's format discipline (the format is hosting-agnostic).

Read the archive

Jeremy Howard — llms.txt site discovery

A markdown file at /llms.txt to make sites LLM-readable.

Proposed September 2024 (fast.ai / Answer.AI). Modeled after robots.txt + sitemap.xml. Now adopted as a Chrome Lighthouse audit. Site-level discoverability convention; complementary layer to Capsule's artifact-level discipline — a site that hosts capsules should have an /llms.txt that indexes them. htmlcapsule.org has one.
